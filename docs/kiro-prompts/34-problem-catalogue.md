# Spec 14: `problem-catalogue` (pack importer, catalogue tables and API, publish/unpublish)

Added 14 Nov 2026 after the spec-gap review (docs/kiro-log/spec-gaps-2026-11-14.md). Written by Kiro in spec mode only; no implementation until Brighton approves.

```
Spec: problem-catalogue. Close the gap between Grimoire packs in git and the running server. Read #[[file:docs/system-design.md]] (§2, §4 data model, §5 run lifecycle, §9 API, §10), #[[file:docs/requirements.md]] (PRB-1, PRB-2, PRB-3, PCK-1 to PCK-3, ADM-1, E14, walkthrough W3), .kiro/specs/grimoire-packs/ (design "Import (later spec)", GRM-54 ProblemRecord, the three starter packs), .kiro/specs/run-lifecycle/ (ProblemLookup / ProblemRef seams in crates/server/src/seams.rs, submissions table), .kiro/specs/judge-sandbox/ (ProblemTests, PackRunner, image digest, hidden tests are worker-owned), .kiro/specs/ide-workspace/ (it needs GET /api/problems/{slug} and GET /api/languages; its T02 and T13 are blocked on this), .kiro/specs/hints/ and .kiro/specs/dashboard-fsrs/ (they expect a "catalogue spec" to own problems, concepts, problem_concepts and the problem_slug foreign keys), .kiro/specs/auth/ (capabilities, the judge demo account), and every file in .kiro/steering/. If docs/kiro-prompts/33-starter-pack-hardening*.md exist, read them for context only; this spec owns import behaviour.

Cover:
1. Postgres schema (SQLx migrations sorted after the existing ones): tracks ("Crypts"), concepts, problems, immutable problem_versions (content hash, engine/generator version, created_at), problem_concepts, public examples, server-only hidden tests and reference solution, publication state. Add the foreign keys hints and dashboard-fsrs deferred to "the catalogue spec". Least-privilege roles: the server's role cannot read hidden tests or references; only the judge role can.
2. Importer: a command (choose the right home under .kiro/steering/structure.md; grimoire stays free of database types) that reads packs/<slug>/, requires static validation to pass (and records whether sandbox validation passed), converts via ProblemRecord, and writes one transaction per pack. Idempotent (re-running with no change is a no-op), versioned (a content change creates a new problem_version; old versions stay for history and ghost determinism), dry-run mode with a diff, never imports draft packs or underscore packs (_test, dogfood), never deletes history. Decide where hidden expected outputs are computed (at import through the judge's sandbox runner, or by the judge) and justify it against system design §5 point 5.
3. Publish and unpublish (ADM-1) as CLI commands for the operator. No web admin UI and no new roles in this spec. Unpublished problems disappear from the API but keep their submissions.
4. Public read API: GET /api/problems (filters by track, concept, difficulty; PRB-1; solved/attempted status for a signed-in user if auth is present, PRB-2), GET /api/problems/{slug} (statement, examples, constraints, per-language signature and starter code, authored hint rungs as the hints spec allows; PRB-3), and GET /api/languages unless another spec already defines it (check language-drivers and ide-workspace first; do not duplicate). Hidden tests, references and known-ghost internals never appear in any response, log or SSE event.
5. Real implementations of the run-lifecycle ProblemLookup seam and the stored ghost lookup ide-workspace T02 needs, replacing test seams without breaking existing tests.
6. Dev and demo seeding: a documented way to import the starter packs into a local database for tests and for the judge demo account.
7. Tests: property tests for idempotence and versioning, pg_ integration tests (ignored by default, use DATABASE_URL), API tests proving no secret field leaks, and a test that drafts and underscore packs are refused.
Mark [SUPERVISED] every task touching database privileges, hidden data or the importer's trust decisions.
```
