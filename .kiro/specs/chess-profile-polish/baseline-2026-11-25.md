## Chess

- Shared sprite: `web/static/break/pieces-steel-night.svg` — 8.6 KB, viewBox `0 0 40 40`, groups `wp…wk`, `bp…bk`, `crown`; each group carries `.sh` shadow ellipse, `.hi` highlight, `stroke` outline. Flat fills only — no gradients. White = `#e6e1d3` (bone), black = `#2b2342` (night-violet). CPX-1 calls for carved ivory + restrained candle-gold (white) and obsidian with bright neutral/steel edging (black) with premium dimensional shading — current art does not meet that brief.
- Shared mount: `web/src/lib/break/chess/theme.js` — `PIECES_URL` same-origin static path (required by `connect-src 'self'`), `tileSize: 40`, `cssClass: 'steel-night'`, 300 ms animation, lazy `cm-chessboard` import. Frozen `CHESSBOARD_STYLE`, `LAST_MOVE` marker (`marker-frame-primary`), `showLastMove`/`clearLastMove` helpers.
- Board colours: white squares `var(--accent-moss)` `#8a9e8f`; black squares `var(--accent-moss-deep)` `#26332c`; border `--border`/`--border-strong`; coordinates `--text-muted`/`--text`/`--accent-moss-deep`; markers `--accent-candle`/`--accent-candle-glow`. `.break-board` = `min(100%, clamp(280px, calc(100dvh - 20rem), 640px))`, square aspect.
- Live bot page (`/break/bot`, 390×844): board rendered 358×358 px, 32 pieces, groups scaled ≈1.029 — tile art scales with square as required.
- Routes using the board: `/break/bot`, `/break/puzzle` (+ `/break` hub, `/break/memory` unrelated). Both share `mountThemedBoard`.
- Existing tests: `web/src/lib/break/chess/pieces.test.ts` (sprite contract: ids, `stroke`/`.hi`/`.sh`, <40 KB, vector-only), `theme.test.ts` (frozen style, markers, lazy import), `chess-css.test.ts` (board CSS + `.steel-night` square fills present).

## Live production defect found (every page)

`web/src/app.html` lines 6–9 place the literal token `%sveltekit.head%` inside an HTML comment. SvelteKit still substitutes the token there, so head markup is injected inside the comment and the remaining comment text renders as visible text at the top of every page (confirmed live: "appends route tags after any static ones, so a generic title or description meta here would win over every route — keep them out of this shell. —→" above the header). Fix: remove the token from inside the comment.

## Profile (`/settings/account`)

- Identity block: `.profile-identity` — 88 px `.profile-avatar` floated left beside text column; name (display_name || handle) `<h2>`; `@handle`; email shown in identity (should live only in private account details, once); raw `country` code rendered ("ZA" not "South Africa"; "Country not set" fallback); `Edit profile` button when `can.edit_profile`.
- Decorative `.crypt-key` (88 px `crypt-key-128.webp`) rendered to the right of identity, `tabindex=0` focus target — competes with identity on narrow screens per design; keep on desktop, de-emphasise on mobile.
- Section order (must preserve): Sign-in methods → Security → Sessions → Delete account. Existing test `page.test.ts` asserts this order + crypt-key affordance + "no storage message" (PR #133 already removed the avatar storage line — merged, `a7e07f2e`).
- `session.user` fields available: `handle`, `display_name`, `email`, `country` (alpha-2 or legacy unknown), `avatar_url`, `avatar_editable`, `providers`, `is_demo`, `profile_complete`; `session.capabilities.edit_profile` gates editing.

## Shared profile form (`web/src/lib/auth/ProfileForm.svelte`)

- Used by `/settings/account` (inline panel) and `/onboarding` (initial setup, `submitLabel="Continue"`).
- Current: label "Display name" (spec: **"Full name"**), free-text 2-char "Country code" input with `placeholder="ZA"` (spec: searchable accessible country selector, readable names, ISO alpha-2 stored, optional clearing), no cancel button (spec: explicit cancel discards draft), "Saving…" busy state present, `role="status"`/`role="alert"` feedback present, updates `session.user` after PATCH only — that part already correct.
- API: `PATCH /api/me/profile` via `patchProfile({display_name, country|null})` → `{user, capabilities}`; Rust `ProfilePatch` trims name (1–80), normalises country casing, accepts two ASCII letters; unknown/legacy codes pass through unchanged — client must not silently rewrite them.
- Existing tests: `ProfileForm.test.ts` (save seam), `page.test.ts` (account), onboarding tests under `web/src/routes/onboarding/`.
