# Stage S5: hidden tests and generator (private tree)

## Inputs
- The S4 reference, the S2 statement and the sample inputs in `meta.toml`.
- Your own hand-derived expected values. Do not take them from running code.

## Do
1. Write `hidden.toml` in the private tree with at least eight curated cases. Each case has `input`, a hand-derived `expected` and a `why` note of 1 to 120 characters. The cases cover:
   - empty or minimal input;
   - a single item;
   - the maximum length the statement allows;
   - boundary values;
   - negative values, only where the statement allows them;
   - duplicate or equal values;
   - the input of each known ghost (written in S6).
2. No case may duplicate a sample, another case, or a value on the retired list. You do not see that list, and a check reports any clash by code only.
3. Write `generator.toml` in the private tree with `seed` (an integer) and `hidden_count` between 5 and 50.

## Output
- `hidden.toml` and `generator.toml` (private tree).

## Stop condition
`HID-01` to `HID-04` pass. The checks are run by the validator on the assembled tree (S9).

## Checklist items this stage must answer
- `RV-correctness-2`: every hidden expected value follows from the statement.
- `RV-difficulty-2`: at least one hidden case needs the key idea of the problem.

## Rules
- Do not run the reference to get expected values. Derive them by hand (PIP-12).
- Do not copy a sample into the curated cases.
- Hidden values never enter a public file, a summary or a log.
