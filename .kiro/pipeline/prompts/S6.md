# Stage S6: incorrect programs and known ghosts (private tree)

## Inputs
- The S4 reference, the S2 statement and the S5 cases.

## Do
1. Write at least two incorrect programs in `incorrect/` in the private tree. Each one is a realistic beginner mistake, for example:
   - an off-by-one bound;
   - a wrong starting value;
   - forgetting the last element;
   - mixing up index and value;
   - mishandling empty input.
   Do not use a contrived bug such as calling `abs()` on a total (PIP-13).
2. Write `known_ghosts.toml` in the private tree. Each `[[ghost]]` has `id`, `program` (for example `incorrect/off_by_one.py`), `kind`, `input`, `got`, `concepts` and `explanation`.
3. Hand-trace each `got` value. Record the trace in your session notes, not in a file.
4. Each explanation follows GRM-31. It must not claim that its input is the smallest possible one.

## Output
- `incorrect/*.py` and `known_ghosts.toml` (private tree).

## Stop condition
`GRM-28` to `GRM-33` pass, and there are at least two ghosts (`GHC-01`). The sandbox reproduces each ghost later (S11).

## Checklist items this stage must answer
- `RV-ghost-1`: at least two ghosts, each a realistic beginner mistake.
- `RV-ghost-2`: each explanation matches its program.

## Rules
- Do not run an incorrect program on the host. Code runs only in the judge sandbox (PIP-37, PIP-38).
- Describe the ghost as a minimized counterexample the engine found, never as the smallest possible input (GHO-6).
